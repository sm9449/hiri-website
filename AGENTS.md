# AGENTS.md

## Project

HIRI Website

Public-facing marketing website for HIRI Creative Writing.

Purpose:

Introduce visitors to HIRI, communicate the value of the course, establish credibility, explain the learning methodology, and convert visitors into enrolled students.

The website is not the learning platform.

The learning platform lives separately at:

app.hiri.uk

The website exists to attract, educate, and convert prospective students.

---

# Technology Stack

Frontend:

* Next.js
* TypeScript
* App Router
* Static Generation
* SEO-first architecture

Hosting:

* Render

Domain:

* hiri.uk

Learning Platform:

* app.hiri.uk

Backend API:

* api.hiri.uk

---

# Development Philosophy

Build for:

1. Clarity
2. Trust
3. Conversion
4. SEO
5. Performance

Every page should answer:

* What is HIRI?
* Why should I trust it?
* How does it help me?
* What happens next?

Avoid unnecessary animations, gimmicks, and visual clutter.

---

# Brand Positioning

HIRI is not an AI writing tool.

HIRI is a guided creative writing education program.

The focus is:

* imagination
* storytelling
* creativity
* writing confidence
* deliberate practice

AI supports learning.

AI is not the product.

Human teaching remains central.

Miss Shaanzae Shahid is the lead educator.

---

# Website Goals

Primary Goal:

Convert visitors into enrolled students.

Secondary Goals:

* Build credibility
* Demonstrate teaching quality
* Showcase curriculum
* Explain learning outcomes
* Support SEO discovery

---

# SEO Principles

Every page must:

* Have a unique title
* Have a unique meta description
* Use semantic HTML
* Use proper heading hierarchy
* Include internal links where relevant

Avoid:

* duplicate content
* keyword stuffing
* hidden content
* autogenerated SEO text

Content must read naturally.

Humans first.

Search engines second.

---

# Performance Requirements

Target:

* Lighthouse Performance > 90
* Lighthouse SEO > 95
* Lighthouse Accessibility > 90

Avoid:

* large video backgrounds
* unnecessary JavaScript
* excessive dependencies

Prefer static rendering whenever possible.

---

# Design Principles

Visual style:

* Professional
* Modern
* Premium
* Educational

Not:

* Corporate
* Academic
* Childish
* Gamified

Use whitespace generously.

Prioritize readability over visual effects.

---

# Content Rules

All claims must be supportable.

Do not invent:

* student testimonials
* student numbers
* success rates
* awards
* certifications

Use real information only.

---

# Conversion Principles

Every page should contain a clear call-to-action.

Preferred CTAs:

* View Course
* Start Learning
* Explore Curriculum
* Enrol Now

Avoid aggressive sales language.

The tone should be confident and educational.

---

# Accessibility

Maintain:

* keyboard navigation
* sufficient colour contrast
* alt text for images
* accessible forms

Accessibility is not optional.

---

# Future Architecture

hiri.uk

app.hiri.uk

Student Platform

api.hiri.uk

Writeflow Backend
